# 票券方案購買與生命週期業務驗收測試案例手冊 (Acceptance Test Matrix)

> **版本**：v1.0  
> **適用對象**：客戶專案負責人、產品經理（PM）、品質保證團隊（QA）、業務驗收小組  
> **編制原則**：全手冊採用**資訊隱蔽（Information Hiding）**技術，將底層程式碼、資料庫語法與內部元件封裝，轉化為易於理解、對齊業務邏輯的驗收規格。所有案例皆以實際營運情境設計，時間標準採用**台灣標準時間（UTC+8）**。

## 一、 模組詳細驗收案例清單

### 模組 1：新客首購資格檢核 (NEW_ONLY) — 12 項案例
針對新會員入會推廣方案的優惠權益進行嚴格審查，避免老會員偽裝或重複享受優惠。

| 案例編號 | 業務情境說明 | 前置條件與操作 | 預期業務驗收結果 |
| :---: | :--- | :--- | :--- |
| **TC-N01** | 入會黃金期內正常查詢 | 9/1 註冊成為學員，分別於 9/1、9/30 查詢新客方案 | **允許購買**：在 30 天效期內，新客方案正常展示與選購。 |
| **TC-N02** | 入會剛滿 30 天翌日查詢 | 9/1 註冊，於 10/1 00:00 查詢新客方案 | **拒絕購買**：已滿 30 天優惠期，系統自動隱藏或阻擋購買。 |
| **TC-N03** | 跨日邊界時間一致性 | 會員於註冊日 00:01 或 23:59 建立帳號 | **一致性驗證**：同一日曆天註冊之會員享有相同的截止天數基準。 |
| **TC-N04** | 會員入會時間資料缺失 | 會員帳號未完整記錄正式獲派學員資格之時間 | **安全拒絕**：無明確入會時間依據時，不予放行新客優惠。 |
| **TC-N05** | 跨國時區入會時間校正 | 會員由境外或 UTC 8/31 16:30 註冊（換算台灣為 9/1 00:30） | **精準校準**：系統統一以台灣時間 9/1 作為入會日曆天起算。 |
| **TC-N06** | 本地時間儲存防重複校正 | 已完整儲存台灣標準時間之學員紀錄 | **計算正確**：時間轉換不產生累加偏移。 |
| **TC-N07** | 曾持有同專案任一狀態票券 | 會員歷史曾持有該專案票券（無論未啟用、使用中、過期、已用完或已取消） | **終身限購一次**：凡曾建立過正式票券，一律永久阻擋再次購買同一專案。 |
| **TC-N08** | 票券取消但訂單已結帳 | 會員線下取消該票券，但原始訂單付款狀態仍為成立 | **資格不復原**：曾享受並完成訂單者，不可重買新客專案。 |
| **TC-N09** | 訂單退費但票券未註銷異常 | 歷史帳務異常情況，訂單標註取消但票券紀錄仍在 | **防弊阻擋**：只要有實際票券產出歷史，仍判定為已享受過新客專案。 |
| **TC-N10** | 僅建立未付款訂單但未繳費 | 會員曾下單新客方案，但超時未繳費且從未生成有效票券 | **保留權益**：未成案交易不消耗新客名額，會員仍可選購。 |
| **TC-N11** | 選購不同方案或他人購買 | 同家族不同 SKU 方案，或其他會員購買新客方案 | **精準隔離**：僅阻擋個人本人的同專案重複購買，不影響其他方案。 |
| **TC-N12** | 歷史帳務稽核異常防護 | 面對歷史資料缺失稽核日誌時之容錯測試 | **系統穩定**：系統平穩拒絕，不發生系統崩潰或例外錯誤。 |

### 模組 2：續約資格、家族傳承與寬限期 (RENEWAL) — 14 項案例
檢驗會員舊票券如何平滑繼承至新續約方案，並保障提前續約與過期寬限期。

| 案例編號 | 業務情境說明 | 前置條件與操作 | 預期業務驗收結果 |
| :---: | :--- | :--- | :--- |
| **TC-R01** | 持有多張同家族票券（舊票過期、新票有效） | 舊票 A 已逾期，新票 B 尚在有效期內 | **智慧承接**：以最新票券 B 作為基準，順利核准續約專案。 |
| **TC-R02** | 最新票券已失去資格，更舊票券看似符合 | 最新票 C 已超期失效，試圖回溯使用更早的票券 A | **防範跳票**：嚴格鎖定「最新來源票券」，不可倒退承接失效舊票。 |
| **TC-R03** | 來源票券狀態不合格 | 來源票券為已取消、尚未生效之未來票券，或屬於跨系列家族 | **安全阻擋**：不認列為合格續約來源，不開放購買續約專案。 |
| **TC-R04** | 堂票提早用罄（Depleted）之起算 | 堂數扣完提早結束，記錄有實際用完日期 | **動態算期**：以「實際用完日期」作為起算點加上 9 天寬限期。 |
| **TC-R05** | 寬限期第 9 天與第 10 天邊界 | 會員於原截止日 + 9 天當日 / + 10 天當日發起購票 | **精準判斷**：第 9 天 23:59 前可購買；第 10 天 00:00 起判定逾期拒絕。 |
| **TC-R06** | 寬限期當天退訂續約票 | 寬限期最後一天 23:50 取消，當日 23:59 前重購 | **當日保障**：原寬限期當天取消者，當天結束前仍允許重訂。 |
| **TC-R07** | 提前續約票取消後之重購效期 | 原票效期至 9/6，於 9/5 提前取消續約票 | **保留原有寬限**：9/6 23:59 前均可重訂，9/7 寬限期起算。 |
| **TC-R08** | 寬限期內提前取消之重購限制 | 於寬限期內取消續約票，測試次日重訂行為 | **防囤防佔**：取消後僅限當天救援重訂，隔日不可無限制復原。 |
| **TC-R09** | 凌晨取消之非 24 小時日曆制 | 9/5 00:01 取消續約票，測試重訂時間 | **日曆日原則**：採當日日曆日（至當日 23:59:59）而非滾動 24 小時。 |
| **TC-R10** | 連續多次取消與重訂操作 | 會員於允許範圍內反覆退訂再重訂 | **不被重置**：原來源票券之原始截止日絕對固定，不得被無限期延後。 |
| **TC-R11** | 已存在未生效之續約繼承票 | 舊票 A 已經成功購買了續約票 B，試圖再買一張續約票 C | **防重複續約**：每一張舊票僅能繁衍承接一張有效新續約票。 |
| **TC-R12** | 具備續約資格時選購標準方案 | 會員完全符合續約資格，但主動點選一般標準方案 | **自由選擇**：系統同時開放一般標準方案，會員可自由依定價購買。 |
| **TC-R13** | 跨方案家族續約限制 | 手持團體課程舊票，點選器械皮拉提斯續約專案 | **家族隔離**：方案家族代碼（Family Code）不符，拒絕續約購買。 |
| **TC-R14** | 舊票尚未生效之續約限制 | 舊票生效日為下週，此時嘗試申請續約 | **拒絕辦理**：票券必須已生效開始使用，方可申請接續之續約方案。 |

### 模組 3：續約票取消與退訂保護 (CANCELLATION) — 10 項案例
驗證購買後尚未使用的票券能否安全退款取消，並防止「已上課卻退票」等惡意漏洞。

| 案例編號 | 業務情境說明 | 前置條件與操作 | 預期業務驗收結果 |
| :---: | :--- | :--- | :--- |
| **TC-C01** | 未生效排隊中續約票取消 | 續約票處於排隊等待生效中，會員申請退訂 | **核准取消**：無爭議退訂，舊票券恢復可承接狀態。 |
| **TC-C02** | 舊票已過期，新續約票啟用但全新未使用 | 舊票已過期，新票剛生效但會員完全未預約上課 | **核准取消**：查無使用紀錄，允許退訂，並即時更新系統狀態。 |
| **TC-C03** | 取消後再次重訂之家族繼承鏈 | 續約票 B 取消後重訂票券 C | **鏈結完整**：票券 C 繼續承接舊票 A，票券 B 保留取消歸檔紀錄。 |
| **TC-C04** | 堂票已核銷使用至少一堂 | 續約購買的堂票已有 1 堂簽到扣堂紀錄 | **嚴格拒絕**：票券已產生實質消費，系統全面鎖定禁止退訂。 |
| **TC-C05** | 月票已有入場簽到紀錄 | 續約購買的月票已有入場運動或預約上課紀錄 | **嚴格拒絕**：月票一旦有使用事實，系統全面禁止退訂。 |
| **TC-C06** | 月票已生效但經核對全無使用事實 | 月票處於生效天數內，但系統確鑿證明無任何打卡紀錄 | **彈性防護**：確認無任何使用事實，方可核准取消。 |
| **TC-C07** | 非續約票券或已過期票券申請取消 | 試圖對已過期、已用完或一般標準票發起取消 API | **安全攔截**：不符合取消規則之票券一律拒絕處理。 |
| **TC-C08** | 前端按鈕狀態與後端 API 檢驗一致性 | 畫面上的「申請退票」按鈕狀態與後端真實檢核 | **一致性保障**：前端顯示可退時，後端必定合規；後端不可退時前端禁按。 |
| **TC-C09** | 門市上課打卡與線上退票同時併發 | 會員在櫃檯簽到打卡上課的同一瞬間，手機點擊退票 | **防弊鎖定**：高並發防護，確保「先簽到則退票失敗」，絕不容許已上課卻退費。 |
| **TC-C10** | 堂數沖銷還原後之偽未消費防範 | 曾扣堂後因爭議人工作廢沖銷，使剩餘堂數看似全滿 | **深層稽核**：系統以「有無實際使用履歷」判定，不單看剩餘數字。 |

### 模組 4：多票券排隊調度與單堂票讓位 (FIFO & QUEUE) — 12 項案例
處理會員擁有多種票券時的「全域單一啟用」、「先進先出」及「單堂票彈性讓位機制」。

| 案例編號 | 業務情境說明 | 前置條件與操作 | 預期業務驗收結果 |
| :---: | :--- | :--- | :--- |
| **TC-S01** | 單堂票使用中，新購買主力月票/套票 | 會員手持生效中的單堂票，隨後購買了長期方案 | **智能讓位**：單堂票自動暫停讓位，主力方案立即生效，全域維持單一主力。 |
| **TC-S02** | 單堂票讓位後的狀態完整性 | 單堂票退回等待佇列 | **資產保全**：堂數、付款金額、票券編號不變，不扣除效期。 |
| **TC-S03** | 主力票券用畢，後方仍有主力排隊票券 | 長期票券 A 結束，後方同時有長期票券 B 與單堂票 | **主力優先**：系統自動優先啟用長期票券 B，單堂票繼續保留等待。 |
| **TC-S04** | 主力票券全數用畢，無其他排隊票 | 長期主力票券期滿結束，帳戶中僅剩待命的單堂票 | **自動喚醒**：單堂票自動按先進先出（FIFO）順序喚醒啟用。 |
| **TC-S05** | 新購主力票券設定在未來日期生效 | 新購主力票券之生效日設於下個月 | **平順過渡**：在主力票生效前，不強制單堂票讓位，保障過渡期權益。 |
| **TC-S06** | 帳戶僅有未生效單堂票時申請續約 | 會員有排隊單堂票，欲為即將到期的主力票申請續約 | **暢通無阻**：單堂票不被視為主力排隊衝突，允許順利續約。 |
| **TC-S07** | 帳戶已有其他主力票排隊中申請續約 | 帳戶已有一張排隊待生效的長期月票，欲再買第二張 | **防囤衝突**：系統攔截阻擋，避免會員過度排隊囤票。 |
| **TC-S08** | 續約票取消後單堂票喚醒，隨後又重訂續約 | 續約票退訂使單堂票短暫生效，會員又於當日重訂 | **反覆調度穩定**：單堂票再次無損讓位，新重訂票券正常排隊接續。 |
| **TC-S09** | 多張不同類型票券同時在佇列等待 | 佇列同時存在：直接續約票、一般主力票、單堂票 | **優先順位明確**：續約/主力票 > 單堂票；同等級票券按購買先後排序。 |
| **TC-S10** | 不同運動家族的主力票券併存 | 會員同時持有瑜珈月票與健身房月票 | **全域排隊穩定**：維持系統全域排隊邏輯，避免跨家族產生使用衝突。 |
| **TC-S11** | 系統定期排程多重對帳校驗 | 每日夜間批次對帳重複執行佇列調度演算法 | **狀態等冪**：計算結果絕對穩定，堂數不增不減、狀態不反覆跳動。 |
| **TC-S12** | 購票、讓位與取消操作同時多工發生 | 多個終端同時對同一會員發起購票與讓位操作 | **併發一致性**：系統鎖定防護，全域精準維持僅一張有效票券生效。 |

### 模組 5：註冊流程與全域資格審查 (REGISTRATION) — 11 項案例
驗證新進會員註冊時的方案選購流程，防範跨過權限繞過購買。

| 案例編號 | 業務情境說明 | 前置條件與操作 | 預期業務驗收結果 |
| :---: | :--- | :--- | :--- |
| **TC-E01** | 新會員註冊頁面之方案目錄展示 | 訪客進入會員註冊頁面瀏覽可購買方案 | **合規展示**：正常展示一般無限制方案，無需預先登入或建置假資料。 |
| **TC-E02** | 註冊頁面嚴格排除限制性專案 | 訪客於註冊頁面查看推薦清單 | **隱藏限制方案**：續約方案（RENEWAL）等專屬方案自動過濾不展示。 |
| **TC-E03** | 營運後台新增資格規則但未開放註冊 | 新建特定企業員工方案，未勾選「開放註冊購買」 | **自動隔離**：註冊清單自動排除該方案，無需人工改動系統程式。 |
| **TC-E04** | 多重複合限制規則之方案 | 方案同時掛有兩種以上資格規則，其中一項未開放註冊 | **嚴格把關**：任一規則不符即全案在註冊端排除。 |
| **TC-E05** | 方案配置未知或未支援之規則代碼 | 營運後台設定了系統尚未支援的新規則名稱 | **安全保險**：系統自動視為「不符合資格」進行阻擋，防止異常漏洞。 |
| **TC-E06** | 後台資料庫設定限制性規則之完整性 | 後台人員設定新規則 | **安全機制**：限制條件必須完整反映於審核引擎中，不容許無條件放行。 |
| **TC-E07** | 註冊流程嘗試直接提交續約方案下單 | 惡意使用者竄改註冊封包，強行提交續約專案代碼 | **交易中斷**：後端即時阻擋，整筆交易回滾，不留下不合規之會員與票券。 |
| **TC-E08** | 註冊完成後，切換為在籍學員專屬購買 | 完成註冊並獲派學員身分，進入個人專區選購 | **即時解鎖**：身分切換成功，符合新客條件即可看見並購買新客方案。 |
| **TC-E09** | 非有效學員身分之會員嘗試購票 | 會員帳號遭停權、未通過審核或 Profile 遺失 | **全面阻擋**：不因具備註冊 Context 而放寬，嚴格拒絕購買。 |
| **TC-E10** | 瀏覽方案時有效，結帳時已過期 | 會員在寬限期最後 1 分鐘開著網頁，跨日後才點擊付款 | **即時攔截**：付款時啟動二次覆核，逾期則交易失敗，防範超期漏洞。 |
| **TC-E11** | 註冊時嘗試建立未付款訂單規避檢核 | 註冊時試圖以未付款訂單鎖定未開放之方案 | **建單攔截**：在建立未付款訂單當下即執行阻擋，不允許延後付款繞過。 |

### 模組 7：訂單結帳、價格防護與交易安全 (PAYMENT) — 7 項案例
驗證金流支付階段的雙重覆核機制，確保高並發與價格波動時的交易正確性。

| **TC-P02** | 訂單建立後，方案後台發生調價 | 建立訂單時為 $1,000，結帳前被後台調價為 $1,200 | **價格保護**：付款時偵測價格異動，即刻攔截交易並回報價格已變更。 |

## 二、 驗收執行與通過判定標準 (Exit Criteria)

為達成高標準的專案交付品質，驗收測試應達到以下標準方可視為合格：

1. **核心案例 100% 通過**：上述 72 項業務驗收案例之執行結果必須與預期行為完全一致，不允許任何邏輯偏差。
2. **邊界時間精準對齊**：針對台灣標準時間之午夜跨日（23:59:59 與 00:00:00）、30 天入會期及 9 天寬限期之邊界，結果判定不得產生誤差。
3. **無任何越權或繞過漏洞**：所有透過非正常路徑、偽造封包或延遲付款試圖規避資格審核之情境，皆必須被安全防線成功攔截。
4. **高並發交易零衝突**：在多終端同時對同一會員發起購票、退票、續約承接與打卡上課時，系統狀態保持強一致性，絕不產生幽靈票券或重複扣費。
