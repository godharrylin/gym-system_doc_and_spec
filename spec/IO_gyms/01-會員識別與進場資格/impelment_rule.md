建立日期：2026-10-04。狀態：後端會員識別、基本票券資格與共用生命週期已實作並通過本機非 SQL 自動測試；SQL 整合、裝置／課程／占用串接及現場驗收未完成，不代表完整進出功能可上線。

## 目標與範圍

建立真正的進出電話識別及學生票券判斷，不重做已完成的後台會員模糊搜尋。

## 已確認規則

- 客人進出只接受台灣手機 `09xxxxxxxx`（09 開頭、共十位數），以完整電話精確識別；無電話、格式不符或不存在時不放行。
- 註冊／編輯的其他數字輸入與後端格式驗證暫不調整，不批次修改既有電話資料。
- 進場要求 `users.usr_active = 1`，只採用 `user_role.user_role_is_active = 1` 的角色。
- 啟用的 Admin／Staff／Instructor 優先，兼任 Student 不以學生身分扣堂；工作人員角色停用但 Student 啟用時，改走學生票券驗證。
- 沒有上述適用角色時拒絕進場，顯示「尚未註冊會員」；帳號停用的拒絕訊息另於技術設計定義，不自行套用相同文字。
- Student 有角色卻缺少 `sdt_profile`：進場拒絕，顯示「會員資料異常，請洽工作人員」並記錄原因，不誤報票券過期。
- 出場仍需可識別電話，但不因帳號／角色停用、profile 缺漏、票券過期或額度不足阻擋；異常需記錄。
- Student 共用票券生命週期及非單堂票優先規則，不將列表 Current Plan 當授權。
- 共用應用服務同步 `sdt_profile` 快照；快照不單獨作最終授權依據。
- 票券整天效期依台灣日期判斷；過期學生進場拒絕，已識別使用者出場不因過期／額度不足拒絕。

## IO-04 已確認：票券分配、額度占用與缺票續堂

確認日期：2026-10-06。狀態：商業規則已確認，技術設計及實作未完成。

### 1. 當前票券與該堂票券的區別

- 階段 01 在進場時整理當前票券並檢查基本資格；不因此把進場時使用的票永久固定為該堂扣堂票券。
- A 以「出席截止時整理後的票券」為準，固定學生與該堂實際使用的 pass 關聯。
- 截止後 B 不依當下 Current Plan 或 profile 快照重新選票，須結算該堂已固定的票券及占用。
- 若緩衝期票券改變，暫占如何移轉、A 晚跑如何還原截止時票券資格，屬於後續技術設計；不能直接拿補跑時才買的票當成截止前已存在的票。

### 2. 暫占、固定占用與 Pending

- 進場先檢查資格並暫占該堂所需額度；不能等到 A 才首次發現不足。
- 出席尚未確認的緩衝期使用 `Pending`。
- 截止前離場且未回來：不成立該堂出席，釋放暫占；具體釋放及再次回場的資料流程待設計。
- 截止時仍在館內：A 確認出席，堂票暫占轉為固定占用；月票記錄出席，不占用堂數。
- 確認出席後中途離場：保留出席與固定占用，不改回 `Pending`，不因未返回而免除該堂结算。
- 中途離場及返回依進出紀錄判斷；同堂多次進出不重複占用或扣堂。
- 帳面剩餘、待結算占用及可用額度必須區分。暫占／固定占用本身不是正式扣堂，不能因此提前將票券標成 `Depleted`。

### 3. 留館續堂與自動接續

- 相鄰課程的業務處理順序已確認：先結算上一堂 → 共用生命週期服務自動接續符合條件的票券 → 確認下一堂出席及額度占用。
- 學生一直留在館內，不必重新輸入電話或產生新開門事件，仍可自動接續下一張票。
- 下一張票仍須符合既有付款、來源、啟用日期及非單堂票優先規則，不能因排隊而提前越過啟用條件。
- 堂票正常耗盡的 `ended_at` 使用耗盡所對應的課程結束時間，例如 20:00，而不是 B 在 20:10 或更晚的實際執行時間。
- 上述時間決策針對課程扣堂造成的 `Depleted`，不改写一般日期到期或取消的時間規則。
- B 實際執行時間另需保留；背景工作排序、補跑及耗盡後接續的日期計算與階段 05 一起設計。

### 4. 無可接續票券：只記異常

- 截止時仍在館內，但沒有可用票券／足夠可占用額度者，保留該學生的留館／出席事實，不將其當作合法票券授權。
- 在既有 `sdt_att_record` 新增 `sdt_att_record_ticket_eligibility_state`，與出席／離場狀態分開：
  - `Eligible`：有符合規則的票券；堂票已成功占用額度。月票符合票券資格，但不占用堂數。
  - `Ineligible`：沒有可用票券，或沒有足夠可占用額度。
- 缺票案例不強填已耗盡的舊 pass，`sdt_att_record_ticket_id` 可為 NULL；remark 保存具體異常原因。
- `Ineligible` 只記異常，不占用、不扣成負數、不產生欠堂、不補結算，且不能憑這筆紀錄取得同堂回場資格。
- 後來補買票不自動將這堂改為 `Eligible` 或補扣；後續課程另行判斷。
- 程式依資格狀態及正式占用／結算資料處理，不解析 remark 文字決定扣堂。
- B 只處理符合資格的堂票出席及有效占用，仍需防止重複結算；資格欄位不是單獨的開門或扣堂授權。
- Database.md 已記錄該欄位，不能據此推定 GymDB 已完成新增；實際 schema、舊資料 NULL 語意及欄位約束仍需核對。

## IO-11 已確認：台灣日期與後端時間來源

確認日期：2026-10-06。狀態：階段 01 原則已確認，待實作查核；不是功能已完成。

### 1. 日期與時間來源

- 進場資格判斷及後續進出成功、占用、異動紀錄的時間，由後端共用 `IClock` 提供台灣時間，不接受 iPad 時間作為資格或截止判斷依據。
- 票券效期按台灣日期判斷，沿用既有 `DateOnly` 與生命週期規則。
- 到期日整天有效，次日才因日期到期失效；DB 日期欄位存零點不代表到期日零點就失效。
- 不得用 `現在時間 > valid_edate` 直接判斷過期。
- 付款、取消、進出、占用及扣堂相關事件仍保留精確時間，不將所有時間欄位改為零點。
- 課程扣堂造成 `Depleted` 的 `ended_at` 使用課程結束時間，與 IO-04 一致；不改變一般 Expire／Cancelled 的既有規則。
- 背景補跑保留原業務時間與實際處理時間，不能用補跑當下時間覆寫原業務時間。

### 2. 本版不處理的跨午夜排程邊界

- 使用者確認目前沒有跨夜課程，也不考慮下課結算跨午夜的正常排程案例；本版不納入這類邊界，不作為階段 01 的待確認阻擋事項。
- 跨營業日殘留館內狀態屬 IO-08，與跨夜課程不同，不因本項而移除。
- 工作中斷後補跑的資料恢復仍按 IO-05 討論，不藉此改寫已確認的原業務時間原則。

### 3. 實作查核的意義

- 「寫入路徑」是指每個把資料存進 DB 的流程，例如註冊、付款、進出、人工更正及背景結算；不是檔案路徑，也不是新增功能。
- 後續實作時核對各流程產生／保存時間的方式，確保符合本節的同一套規則，不要求使用者重新決定已確認的台灣日期原則。
- 匯入／批次應明確處理來源時區；來源不明的舊資料不可整批直接加八小時。
- 本次只寫入文件，沒有執行全流程時間查核、批次改資料或改動 DB 預設值。

## IO-15 已確認：裝置授權與電話識別邊界

確認日期：2026-10-06。狀態：階段 01 授權原則已確認，裝置管理的具體設計與實作留階段 02。

### 1. 已確認的授權原則

- 兩台 iPad 使用獨立的裝置授權，不持有 Admin 權限或以管理員帳號常駐供客人操作。
- 進／出方向由後端站點設定決定，不以客人可修改的網址、畫面或請求參數作為最終方向依據。
- 客人輸入電話只是識別要進／出的人，不呼叫帳號登入流程，不產生該使用者的 access／refresh token。
- 未授權或已撤銷的裝置不能呼叫進出 API；裝置有效後仍需依既有角色、票券及課程規則處理，不等於無條件開門。
- 工作人員電話的角色放行不會把工作人員的管理權限轉交給裝置；同一個電話用於進場識別與後台登入是不同流程。
- 使用者接受只憑電話可能被冒用的進場風險，包含客人輸入工作人員電話；第一版不增加客人的密碼或驗證碼。

### 2. 日常操作需求

- 初次使用需取得裝置授權；日常下班關機、隔天開機或重新開啟頁面，不應要求每天重新配對。
- 授權遭撤銷、到期無法續期、換機或清除瀏覽器網站資料時的重新啟用，留階段 02 定義。
- 本階段確認的是授權邊界與使用需求，不將瀏覽器授權視為不可複製的 iPad 硬體身分，也不承諾授權永不過期。

### 3. 階段 02 待討論與實作

- 後台產生站點配對碼、裝置啟用頁、初次配對及配對碼的有效期／嘗試限制。
- 更換 iPad、撤銷舊授權、同一站點有效授權數量及切換時機。
- 授權保存方式、到期／續期、Cookie、HTTPS 及必要的請求防護。
- 裝置／站點資料、API 權限策略、狀態顯示及可追溯操作紀錄。
- 此處列的是後續設計範圍，不把先前提出的 Cookie 或配對碼期限範例當作已決定參數。

### 4. 獨立待辦與範圍限制

- 後台管理目前只憑電話登入的安全議題另列待辦，不因客人電話進出風險已被接受而視為後台風險也已被接受或已修正。
- 此待辦不改變本次「客人只輸入電話進出、不登入帳號」的操作需求，不自行加入客人密碼驗證。
- 內網隔離、廠商介面存取限制、NAS、控制服務部署與硬體驗收仍在後续範圍，不因 IO-15 階段 01 已確認就視為完成。
- 本輪已同步總規格、issue 及階段 02 的授權原則與待討論範圍；未實作任何裝置授權、配對或登入修改。

## 驗收案例

- 存在／不存在／空白電話；模糊片段不得識別成完整會員。
- 非 `09xxxxxxxx` 電話不得經客人進出流程放行；註冊／編輯驗證本次不擴大調整。
- 停用帳號不進場；停用工作角色不享工作人員放行，啟用 Student 可依票券驗證；已識別使用者出場不因停用拒絕。

- 工作人員兼 Student 走工作人員流程，不產生學生扣堂。
- Student 到期日當天有效、隔天失效；單堂票無到期日不誤判過期。
- 已取消／耗盡票券及可啟用下一張票，依既有規則處理。
- 單堂票遇可啟用非單堂票讓位，剩餘堂數保留。
- 出場不因票券過期拒絕；無法識別電話仍不呼叫控制 API。
- 進場時暫占，截止前離場未回釋放；截止後離場保留出席及占用。
- 緩衝期票券變更，依截止時整理結果固定該堂 pass，B 不重新選票。
- 相鄰課程先結算、接續票券再確認下一堂，留館不需新進場事件。
- 無票留館記 `Ineligible` 及 remark，不扣負數、不補結算、不授予回場资格。
- 堂票耗盡的業務時間是課程結束時間，不隨背景工作晚跑變動。
