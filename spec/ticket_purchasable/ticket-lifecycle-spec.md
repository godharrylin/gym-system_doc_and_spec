# 票券生命週期規格

## 適用範圍

本文件描述購買成立後，票券如何建立、排隊、生效、到期、承接續約來源，以及取消後如何重試。

## 訂單與付款

- Cash Paid 購買會建立訂單、建立票券 pass，並立即執行 reconcile。
- UnPaid 購買只建立訂單，不建立票券 pass，不占用續約來源。
- UnPaid 訂單付款時會重新驗證價格、方案、學生狀態與購買資格，通過後才建立 pass。
- 註冊來源與歷史 UnPaid 訂單延後付款一律按既有會員情境重驗；付款成功後才可參與啟用排隊。

## 一般票券排隊

目前生命週期設計以全域一張 Active 票券為基礎：

- 每位會員跨家族同時間只應有一張 Active。
- 標準票券付款後可先進入 UnActive queue。
- 排隊順序以付款時間優先，其次以 pass sn 排序。
- 輪到票券生效時，從實際生效日開始給完整效期，不倒扣等待時間。

上述完整效期指一般票券；續約票的日期仍依來源與付款日期計算。候選優先順序為剛結束來源的直接續約、其他可啟用續約、一般票，單堂票最低；同順位再依付款時間、pass sn 排序。未來候選不阻擋後面的可用票，SQL 查詢不再截斷前 100 張；已過期候選標記 Expire，再繼續選取。

## 單堂票

單堂票生命週期語意：

- 單堂票僅以 SKU `SINGLE` 識別，不以家族名稱或所有 PACK 判斷。
- 單堂票沒有固定開始日與結束日。
- 單堂票可以 Active，但優先級低於非單堂票。
- 若有可啟用的非單堂票，已 Active 的單堂票可以讓出 Active slot，狀態回到 `UnActive`，並保留剩餘堂數。
- 非單堂票結束，且沒有其他可啟用的非單堂票時，才再啟用單堂票。
- 排隊中的單堂票不應阻擋一般續約購買。

## 續約票券承接

續約購買成立時會記錄來源票券：

- `renewed_from_pass_sn`
- 來源有效結束日。
- 是否為提前續約。
- 最後一次取消續約票時間，用於判斷取消後重訂期限。

有效結束日判斷：

- 來源票券未用完時，使用 `validEndDate`。
- 來源票券已用完時，使用 `endedAt` 對應日期。

續約票券生效日：

- 提前續約：來源有效結束日隔天生效。
- 逾期但仍在 grace window 內續約：付款日生效。
- 到期日：生效日加方案天數再減一天。

## 取消與重試

續約取消後的規則：

- 已取消的續約 pass 保留 `renewed_from_pass_sn`。
- 取消日會作為後續重訂期限判斷。
- 一般已有任一家族非單堂排隊票券時不可續約，取消重訂例外沿用既有規則。
- 只有 UnActive 續約票可取消；Active 續約票即使未使用也不開放。取消不等於退款。
- 取消後重訂期限為「取消日隔天」與「原始續約截止日」兩者較早者。
- 取消動作不得延長來源票原本的續約截止日。
- 已取消來源票券不可再作為續約來源。

## 逾期與用完

目前狀態語意：

- 票券若今日已超過到期日，應關閉為過期狀態。
- 堂數票最後一次扣堂時，應立即記錄實際用完時間 `endedAt`，不要等排程補登。
- pass 狀態：`UnActive = 1`、`Active = 2`、`Expire = 3`、`Depleted = 4`、`Cancelled = 5`。
- `end_reason`：`Expire = 1`、`Depleted = 2`、`Cancelled = 3`；未結束為 null，不使用 `Expired`。

`endedAt` 用於判斷已用完票券的有效結束日。單堂讓位不寫結束原因／時間，不更改堂數、付款時間或原順位。order item 的 `Cancel` 與 pass 的 `Cancelled` 不互換。

## 需要測試的生命週期案例

- 標準票券付款後立即 Active。
- 有 Active 時，新買標準票券進入 UnActive queue。
- queue 依 paidAt、passSn FIFO 生效。
- 續約提前購買，生效日為來源有效結束日隔天。
- 續約逾期但仍在 9 天內，生效日為付款日。
- 來源票券用完時，以 endedAt 作為有效結束日。
- 已有任一家族非單堂 queue 時不可續約（取消重訂例外另測）。
- 取消未使用續約票後，可在取消後重訂期限內再次購買續約票。
- 若來源票原始續約截止日是 9/5，使用者 9/5 23:50 取消，9/6 00:00 起不可再買續約票。
- 單堂票 Active 或排隊中時，不可因此阻擋續約購買。
- UnPaid 訂單不建立 pass、不占用 queue、不占用續約來源。
