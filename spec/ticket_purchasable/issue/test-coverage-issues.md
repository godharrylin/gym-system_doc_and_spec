# 待補測試事項

## 1. Catalog 查詢測試

建議覆蓋：

- 啟用產品會出現在目錄。
- 停用產品不出現在目錄。
- `HIDDEN` 方案不出現在目錄。
- `NEW_ONLY` / `RENEWAL` 關聯停用時，方案不出現在目錄。
- 全域規則停用時，方案不出現在目錄。
- `EligibilityRuleCodes` 正確輸出。

## 2. Eligibility service 測試

建議覆蓋：

- 沒有 rule code 的方案可購買。
- 找不到 rule handler 時不可購買。
- `AppliesTo` false 時不可購買。
- `IsSatisfiedAsync` false 時不可購買。
- 多個 rule code 必須全部通過。

## 3. NEW_ONLY 測試

建議覆蓋：

- `AssignedAt` 為 null 時不可購買。
- 台灣日曆 30 天內可購買。
- 剛好第 30 天可購買或不可購買，依最終規格固定。
- 超過 30 天不可購買。
- 曾買同 SKU 不可購買。
- 曾買同 SKU 後取消是否可購買，依最終規格固定。
- 台灣 00:00 前後與 UTC 跨日邊界。

## 4. RENEWAL 測試

建議覆蓋：

- 來源票券有效期內可續約。
- 來源票券到期後第 9 天可續約。
- 來源票券到期後第 10 天不可續約。
- 來源票券已用完時，以 `endedAt` 判斷 grace window。
- 來源票券還沒開始不可續約。
- 不同 family 不可續約。
- 已有 successor 不可續約。
- 已有 queued pass 不可續約。
- 同日取消續約後可重試。
- 隔日取消重試不自動放行，需回到一般資格判斷。
- 符合續約資格時，標準方案仍可購買。

## 5. 購買流程測試

建議覆蓋：

- Paid 購買會建立 order 與 pass。
- UnPaid 購買只建立 order，不建立 pass。
- UnPaid 付款成功後才建立 pass。
- 購買者必須包含在受益者清單中。
- 受益者數量不是 1 時，回傳家庭購買不可用。
- `SINGLE` 數量 1 到 5 可購買。
- 非 `SINGLE` 數量大於 1 不可購買。
- 付款方式非 Cash 不可購買。
- 方案停用後不可購買。

## 6. UnPaid 付款重驗測試

建議覆蓋：

- 未付款訂單付款時方案仍有效，付款成功。
- 建單後方案下架，付款失敗。
- 建單後價格變動，付款失敗並回傳 `TICKET_PLAN_PRICE_CHANGED`。
- 建單後 NEW_ONLY 資格失效，付款失敗。
- 建單後 RENEWAL 來源被占用，付款失敗。
- 建單後學生停用或移除 Student 角色，付款失敗。

## 7. 續約併發測試

建議覆蓋：

- 兩筆續約同時承接同一來源，最多一筆成功。
- DB unique index 發生衝突時，API 回傳可理解的業務錯誤。
- 一筆 Paid 與一筆 UnPaid 後續付款競爭同一來源，只有付款重驗成功者成立。

## 8. 生命週期與 FIFO 測試

建議覆蓋：

- 沒有 Active 時，新票券立即 Active。
- 有 Active 時，新票券進入 UnActive queue。
- queue 依 paidAt、passSn 排序。
- Active 到期後，下一張票券以實際生效日開始給完整效期。
- 續約提前購買時，生效日為來源有效結束日隔天。
- 續約逾期但仍在 grace window 內購買時，生效日為付款日。
- 單堂票是否占用 Active slot，依最終規格固定。

## 9. UI/API 測試

建議覆蓋：

- 註冊可購買清單不顯示 `RENEWAL`。
- 既有會員符合資格時顯示 `RENEWAL`。
- 符合續約資格時標準方案仍可顯示與購買。
- 購買成功、取消、付款後重新載入清單。
- 選取方案失效後清除選取。
- 後端拒絕不可購買方案時，前端顯示對應錯誤。
- 台灣跨日情境下，前端日期不偏移。
