# 驗收案例

狀態：部分案例已有單元及 GymDB SQL 驗證，完整情境尚未全部覆蓋；執行證據與缺口見 [05-remaining-alignment-plan.md](05-remaining-alignment-plan.md)。本表列出預期，不表示每列已驗收。日期均為台灣時間，除指定拒絕條件外，其餘基本資格、產品啟用與付款條件預設成立。

## NEW_ONLY

| ID | 情境 | 預期 |
| --- | --- | --- |
| N01 | 9/1 註冊，9/1／9/30 查詢 | 可通過 30 天條件 |
| N02 | 9/1 註冊，10/1 00:00 查詢 | 不可通過 |
| N03 | 註冊日時間為 00:01 或 23:59 | 相同台灣日期有相同截止日 |
| N04 | AssignedAt 缺失 | 拒絕 |
| N05 | 明確 UTC 來源為 8/31 16:30 | 轉成台灣 9/1 00:30，再依 9/1 起算 |
| N06 | 已儲存台灣時間的資料 | 不重複加 8 小時 |
| N07 | 同會員同 SKU 分別有 UnActive／Active／Expire／Depleted／Cancelled pass | 每個狀態都阻擋 NEW_ONLY |
| N08 | 取消 pass，order item 仍 Paid | 不恢復資格 |
| N09 | order item 變 Cancel，但同 SKU pass 仍存在 | 不恢復資格 |
| N10 | 只有 UnPaid 訂單且沒有 pass | 不消耗資格 |
| N11 | 同家族不同 SKU／其他會員同 SKU | 不觸發本人的同 SKU 歷史阻擋 |
| N12 | 錯帳或人工取消／尚無 order_audit_logs | 不產生例外，不依賴 audit table |

建議擴充 `TicketPlanEligibilityServiceTests`，並以 SQL 整合測試驗證實際 pass 查詢，不只驗證 mock 回傳值。

## 共用資格與註冊

| ID | 情境 | 預期 |
| --- | --- | --- |
| E01 | 註冊清單、無資格限制標準方案 | 可顯示，不需要虛構會員 |
| E02 | 註冊清單、NEW_ONLY 或 RENEWAL | 不顯示 |
| E03 | 新增資格 rule，未開放 Registration | 註冊自動排除，不另改 controller |
| E04 | 多個 rule 中一個不支援 Registration | 整個方案排除 |
| E05 | 未知 eligibility code 已輸入 service | 缺 handler，拒絕 |
| E06 | SQL 設定新增限制性 rule | 必須輸出資格 code 或在目錄安全拒絕，不能漏傳變成無規則 |
| E07 | 註冊購買直接送 NEW_ONLY，即使 Student 已在同一流程建立 | 拒絕，交易不得留下不完整註冊／購買結果 |
| E08 | 註冊完成，改走會員購買；符合 N01 且沒同 SKU pass | NEW_ONLY 可買 |
| E09 | 無有效 Student／profile 的會員情境 | 拒絕，不因共用註冊 Context 放寬 |
| E10 | 一般購買與 UnPaid 付款，資格在顯示清單後失效 | 送出／付款時重新拒絕 |
| E11 | 註冊直接提交不開放 SKU 並要求 UnPaid | 建單階段拒絕，不允許延後付款繞過 |
| E12 | 註冊建立一般方案 UnPaid 訂單，後續付款時方案新增 NEW_ONLY，會員仍符合新客條件 | 用 ExistingMember 及付款時規則重驗，成功才發 pass；歷史未付款訂單同規則 |
| E13 | 延後付款時 NEW_ONLY 30 天已失效，或已取得同 SKU pass | 拒絕付款，不標為 Paid、不發 pass、不更新啟用快照 |

以應用層測試與兩支 API 的整合測試確認共用方法真的被呼叫；不能只讓兩支 API 各自複製相同條件。

## 續約來源與期限

| ID | 情境 | 預期 |
| --- | --- | --- |
| R01 | 同家族舊 A 超過期限、較新 B 仍符合 | 用 B 判斷，允許續約 |
| R02 | 最新來源不合資格，更舊來源看似符合 | 不 fallback |
| R03 | 來源為 Cancelled／UnActive、未來開始、不同家族 | 不作合格來源 |
| R04 | 來源 Depleted | 用實際 endedAt 日期算原截止日 |
| R05 | 無取消紀錄，原截止日當天／隔天 | 當天可買，隔天拒絕 |
| R06 | 9/5 23:50 取消，原截止 9/5 | 9/5 仍可重訂，9/6 00:00 拒絕 |
| R07 | 9/5 23:50 取消，原截止 9/6 | 9/6 23:59 可重訂，9/7 00:00 拒絕 |
| R08 | 9/5 23:50 取消，原截止 9/10 | 9/6 可重訂，9/7 拒絕，不能退回一般 grace 放行 |
| R09 | 9/5 00:01 取消，原截止晚於 9/6 | 9/6 全日可重訂，驗證非固定 24 小時 |
| R10 | 多次取消／重訂 | 同來源、最多一張非取消 successor，絕不延長原截止日 |
| R11 | 已有非取消 successor | 拒絕另一筆承接 |
| R12 | 符合續約資格，同時查標準方案 | 標準方案仍可買 |

R10 的重試時間選擇依實作計畫沿用最近一次取消；固定來源原截止日不隨重訂票的日期改變。

## 續約取消與使用

| ID | 情境 | 預期 |
| --- | --- | --- |
| C01 | 未使用的 UnActive 續約票 | 允許取消 |
| C02 | 來源已過期，續約 B 購買即 Active，尚未使用 | 本次不允許取消；Active 續約票取消先作廢 |
| C03 | B 取消後重訂 C | C 承接原來源 A，B 保留 Cancelled 與來源連結 |
| C04 | 堂票已使用至少一堂 | 取消拒絕 |
| C05 | 月票有使用紀錄 | 取消拒絕，不以堂數判斷 |
| C06 | 月票 Active，即使可靠使用紀錄顯示尚未使用 | 本次不允許取消 |
| C07 | 非續約票、已結束票、重複取消 | 拒絕 |
| C08 | canCancel 顯示與取消 API | 相同資料下結果一致；API 仍重新驗證 |
| C09 | 取消與核銷併發 | 不得出現已使用卻取消成功；檢查與寫入在一致鎖定範圍 |
| C10 | 已用再沖銷，剩餘堂數回到總數 | 不可只靠餘額判定未使用；先完成使用紀錄語意查核 |

C10 的 Consume／Reverse 語意先作為商業規格保留；本次維持只有 UnActive 續約票可取消，不因 usage 查詢放寬 Active 取消。

## 單堂票與全域 Active

| ID | 情境 | 預期 |
| --- | --- | --- |
| S01 | Active 單堂票＋新買可立即啟用非單堂票 | 單堂回 UnActive，非單堂 Active，全域仍只有一張 Active |
| S02 | 單堂票讓位 | 堂數、付款時間、pass 編號不變，日期保持 null，無結束原因／時間 |
| S03 | 非單堂票結束，仍有可啟用非單堂票 | 繼續優先非單堂票 |
| S04 | 非單堂票結束，只有單堂票可用 | 依原單堂 FIFO 啟用 |
| S05 | 非單堂票尚未到可啟用日 | 不強迫單堂讓位，不阻擋其他可用候選 |
| S05b | 前 100 張候選都尚未到啟用日，後方仍有可用票 | 不因查詢上限漏掉後方候選；須以實際 SQL 驗證 |
| S06 | 一般續約時只有 UnActive 單堂票 | 不構成 queue 衝突 |
| S07 | 一般續約時有其他非單堂排隊票 | 維持原 queue 衝突限制；另測取消重訂例外 |
| S08 | 取消 UnActive 續約 B 後，期限內重訂 C，且當時有 Active 單堂票 | 單堂讓位，不阻擋 C；堂數不被重設 |
| S09 | 可啟用的直接續約、一般票、單堂票同時排隊 | 續約／非單堂優先，單堂最低；同順位依 paidAt／passSn |
| S10 | Active 非單堂票＋另一家族非單堂票 | 不切換成每家族 Active；新票依規則排隊 |
| S11 | 同一資料重複 reconcile | 結果穩定，不增減堂數、不反覆切換 |
| S12 | 買票／讓位／取消同時執行 | 不產生兩張 Active，快照指向最後有效票券 |

SQL repository 與記憶體替身均需驗證，不能只測排序函式。

## 目錄與保留功能

- HIDDEN 不出現在兩支清單；直接購買與既有 UnPaid 付款都不能繞過目錄。
- FAMILY_ELIGIBLE 資料保留且不套用；不折扣，多受益者仍拒絕。
- 方案下架、改價、會員停用、付款來源已被占用等既有重驗保持有效。
- 兩筆續約同時競爭同一來源，最多一筆成功；確認 SQL 約束與應用層錯誤處理。
- pass／end_reason 序列化使用 D07 精確名稱，單堂讓位仍是 UnActive，付款 Cancel 不混作 pass Cancelled。

## 測試執行與完成條件

優先擴充現有 `tests/gym-system.Application.Tests` 的 eligibility、renewal、domain、register 與 unpaid payment 測試；新增必要 SQL 整合測試驗證真實查詢、狀態更新和鎖定。實作完成後執行相關測試專案，再依修改範圍進行整體 build 與回歸。

完成時應記錄執行命令、結果、實際 DB 驗證範圍與尚未覆蓋項目。只有文件或 mock 通過，不能宣稱 SQL、使用紀錄或併發案例已完成驗收。
