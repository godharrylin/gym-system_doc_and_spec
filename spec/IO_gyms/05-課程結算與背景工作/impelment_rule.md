## 目標與範圍

實作下課十分鐘後的 B 及可恢復的 A／B 背景工作框架，將堂票占用正式結算，避免漏扣或重複扣。

## 已確認規則

- B 依已固定出席及占用扣堂，不以結算時是否仍在館內判斷。
- 出席後中途離場未回仍扣該堂；多次進出不重複扣。
- 月票不扣堂票額度。
- 每場次／學生唯一出席與占用、每筆出席最多正式扣一次。
- 扣堂與已結算標記同一筆資料庫交易。
- 工作狀態持久化，重啟後補處理逾時工作。
- 同一堂補跑先 A 後 B，保存預定與實際執行時間。
- 可以單一背景程式處理多個階段，不必兩個獨立服務。
- 相鄰課程先上一堂 B 結算、接續符合條件票券，再下一堂 A 確認出席；具體工作排序實現與鎖定／恢復待設計。
- 2026-10-23 最新確認：上述接續不是 B 的交易步驟。B 只提交扣堂、核銷、占用 Consumed、必要耗盡標記及結算完成；下一次進場／下一堂 A 確認前置結算已完成後，再由共用票券服務整理接續。留館者由下一堂 A 觸發，不要求重新進場。
- B 結算已固定的 pass 與占用，不依當下 Current Plan 選票；Ineligible 不扣負數、不欠堂、不補結算。
- 課程扣堂耗盡的 ended_at 為課程結束時間；另保留實際處理時間，不覆寫業務時間。
- 共用後端台灣時間；本版不納入跨夜課／正常下課結算跨午夜邊界，不影響工作失敗後的恢復要求。

## 2026-10-25 確認：B 結算、防重及畫面第一版

### 1. 結算流程與精確時間

- B 由後端背景工作自動執行，不依賴學生輸入電話或前端查詢才啟動。
- 依後端台灣時間判斷 `now > class_end_at.AddMinutes(10)`，不採 `>=`。例如 20:00 下課，20:10:00 仍在原回場期限內，B 須在超過該整點後才處理；輪詢排程可能再晚幾秒，不能提前扣堂。
- 每學生獨立交易：重驗 A 固定的出席／票券／占用，扣 1 堂，寫入核銷，將占用轉 Consumed 並連結 usage_sn，必要時標記 Depleted（ended_at 為課程結束時間），最後完成該學生 B 進度。任一步失敗全筆回滾，不影響其他學生。
- 已有本堂一致的正式核銷時不再扣堂；核銷、票券、占用或工作結果不一致時轉人工，不可只靠一個 Manual 標記假裝完成。
- 月票只更新結算工作進度，不扣堂、不新增零堂數的堂票核銷紀錄。
- B 不啟用下一張票，仍依 2026-10-23 決策由下一次進場／下一堂 A 觸發共用服務；跨日未完成 A／B 一律轉人工。此處是目標流程，並非 B 已實作。

### 2. 共用程式端防重，不新增扣堂唯一約束

- 核銷表不新增 idempotency_key；以 attendance_sn ＋ usage_action = Consume 識別本堂已正式扣除。usage_type 只表示 Manual／Auto_Settlement 來源，不能單獨拿來判斷另一堂是否已扣。
- 人工與 B 必須共用結算服務及既定鎖定順序，在同一 DB 交易取得相關學生／票券／出席／占用鎖後，才檢查既有核銷並決定扣堂；不能先查再於另一個交易扣，也不能只靠 rollback 防止並行重扣。
- 不新增這項扣堂 UNIQUE constraint／unique index、外鍵、CHECK 或 rowversion。既有主鍵、占用表的 idempotency_key／唯一索引，以及工作表既有防線均不移除。
- **接受的限制：** 直接 SQL 或其他不遵守共用服務／鎖定流程的程式，仍可能繞過此防重機制；不能宣稱資料庫會全面禁止重複。新入口必須使用同一流程。
- 人工 Consume 同樣減餘額、寫 usage_type = Manual、連結占用 usage_sn 並更新 Consumed／結算進度，整筆交易提交；B 後續核對一致就不重扣。一般直接調餘額不能自動當成本堂已核銷。
- Reverse 不刪原 Consume；同堂反覆沖銷後補扣仍依第一版規則轉人工，不以新增請求或新出席繞過。第六階段負責沖銷實作。

### 3. 核銷表欄位與時間型別提案

- 沿用 sdt_ticket_usage_log，保留實際 usage_sn 主鍵與 pass_id 關聯，不另建立扣堂表，也不把舊文件中的 pass_sn 複合主鍵草案當成實際 schema。
- 核心擴充：attendance_sn int NULL、usage_action varchar(20) NULL、credits_before_snapshot int NULL、recorded_at datetime2(3) NULL；另預留 reversed_usage_sn int NULL 供第六階段指向原核銷。用途、完整 CREATE 與部署狀態見 [Database.md 核銷表](../../../Database.md)。
- 不新增 credits_after_snapshot，沿用 rem_credits_snapshot；不新增核銷 idempotency_key。usage_type 保留來源欄位，usage_action 分辨 Consume／Reverse。
- 最新確認取代先前 datetime 決策：usage_dt 與 recorded_at 均採 datetime2(3)，先更新 Database.md 再經確認套用 SQL 03，保留資料、不重建。C# 維持 DateTime，背景工作／核銷 repository 明確以 DbType.DateTime2 傳遞時間，不修改全域 Dapper 或 JSON 設定。其他表依 IO-17 待辦，後續處理時先提醒確認，不在本次批次改型。
- 新欄位可 NULL 是為相容舊資料，無證據時不回填出席或操作類型；新課程 Consume 的四個核心值由程式要求填齊。Reverse 的增退量表示與完整更正流程在第六階段細化，不因預留欄位視為已完成。
- [核銷欄位擴充 SQL](sql/02-extend-ticket-usage-log.sql) 與後續 [兩欄時間精度 ALTER](sql/03-align-usage-time-precision.sql) 均已於 2026-10-25 經使用者確認後套用 GymDB。共 13 欄，usage_dt／recorded_at 為 datetime2(3) NULL；原 1 筆核銷資料於毫秒精度下核對一致，其餘欄位、索引及約束不變，不回填、不刪資料、不重建。既有 JSON 與 ClassProcessing 啟用設定未修改；schema 查核及程式測試結果分別記錄於目前實作狀態。

### 4. 暫時性錯誤的重試

- 每位學生最多自動嘗試 3 次，包含第一次，不是失敗後再重試 3 次；相鄰自動嘗試至少間隔 15 秒。
- 僅對可辨識的暫時性技術錯誤（如 SQL 逾時／死結）有限重試；每次先回滾失敗交易，重試前重新檢查工作、核銷與占用，不重扣已完成者。
- 資料衝突、不明核銷關聯等直接 NeedsReview，不盲目重試；第三次仍失敗則轉人工，保存原因，不宣告完成。
- 未到重試時間不能因下一次背景 tick 就立即重做；跨過原場次台灣日曆日仍未完成則停止自動處理，改為人工，即使尚未用完 3 次也不例外。

### 5. B 處理中的簡單版畫面（不輪詢、不保留電話）

- B 正在處理目前識別學生時，進場 API 明確回覆「上一堂結算處理中」且不送開門指令；只影響該學生，不等整班處理完，也不阻擋已識別使用者出場。
- 前端收到上述回覆後停止轉圈、清空電話輸入框、恢復可操作，顯示：「上一堂結算處理中，請稍後重新輸入電話並確認進場」。
- 不新增定期查詢／輪詢 API，不自動等待 B 完成、不自動重新驗證或重送進場／開門；學生需重新輸入電話並手動確認，才取得最新資格結果。
- B 已成功：下一次操作正常重驗課程／票券／額度；全部通過才開門，不保證 B 完成就一定能進場。B 異常／待人工：停止轉圈並顯示待處理原因，不因解除處理中就恢復放行。
- 沒有 iPad 操作時 B 一樣自動執行；一直留館者下一堂 A 也由後端工作觸發，不依賴前端查詢。
- **接受的代價：** 無自動完成通知，學生需重新輸入及再次操作；若等待後已超過截止，仍按原時間規則，不因曾遇處理中延長進場資格。
- 本輪只確認「明確收到 B 處理中」時清空電話；其他失敗情境的電話清除規則另行對齊，不藉本次討論擴大修改。控制器逾時／Unknown 仍依既有規則，不因按鈕恢復就自動重送。

## 既有確認：結算異常、補跑與接續日期

確認日期：2026-10-15。以下為目標規則，不代表現有程式已支援。

### 1. 逐學生結算與失敗隔離

- 同堂十人中一人異常，其餘九人仍可正常完成，不採全班一起失敗。
- 異常者保留未完成狀態及原因，不能標記已結算；重跑只處理未完成項目，已完成者不再扣堂。
- 該學生上一堂未完成結算時，暫停其下一堂資格確認；不阻擋其他學生，也不能因系統處理失敗就把該學生標為沒有票券或 Ineligible。
- 暫停、人工待確認及技術失敗須能與票券資格區分；實際狀態名稱、欄位及恢復流程待技術設計，不在本輪擴充資格 enum。

### 2. 固定占用後票券或堂數遭改動

- 固定占用後，若票券遭取消、人工調整堂數等變更使結算依據衝突，停止該筆自動結算，記錄原因，交由工作人員處理。
- 不自動改扣其他票券、不扣負數、不直接宣告完成，也不能無限盲目重試資料衝突。
- 此為 IO-13 的最低結算防線；人工確認後恢復依階段 06 的重驗與原順序處理規則。取消／人工調整的額外允許範圍、回場／占用的其他影響及退款政策不在本輪擴大。
- 原本 Ineligible 的「不欠堂、不補結算」不直接套用至原本 Eligible、但結算發生故障的項目；不得用改為 Ineligible 的方式掩蓋未完成工作。

### 3. A 漏跑且無法還原歷史

- 同堂 A／B 都晚跑時，仍先處理 A 再 B，不以補跑當下館內名單代替原截止歷史。2026-10-23 最新確認：跨過原場次台灣日曆日仍未完成的 A／B 一律 NeedsReview，停止自動補扣／接續並等待人工確認；A 尚未完成以前 B 不得直接扣堂或宣告完成。同日 A 仍依既有歷史／資格檢查處理，衝突或證據不足則待確認。
- 若某學生的進出歷史不足，無法可靠確認截止狀態，標記待人工確認，保存缺少資料的原因；不猜測出席、不直接扣堂，也不直接認定該學生沒有票券。
- 其他具完整依據的學生照常處理；工作進度須能保存部分完成與待確認項目，不讓一筆缺漏阻擋整堂。
- 即使 A 已完成且票券／占用已固定，B 跨日未完成仍轉人工。人工處理也必須沿用原固定資料重驗及防重，不重新選當下 Current Plan，不因確認操作就強制成功。這是待實作要求，不表示 B 已完成。
- 第一版暫緩完整票券歷史重播及三張歷史表提案；接受跨日未完成 A／B 的人工處理成本。階段 06 人工入口仍須完成，不因採用保守分支而省略。

### 4. 共用服務接續日期與第一版範圍

- 來源因堂數耗盡 `Depleted` 結束：符合條件的續約票可在耗盡當天接續，不必等隔天；支援同一天留館續上下一堂。
- 來源因日期到期 `Expire` 結束：維持到期日隔天接續；若較晚付款，仍不得早於付款日期生效，不把這次調整擴大為追溯未付款期間。
- 第一版不自動執行跨日補扣及歷史接續日期重算；跨日未完成工作先人工確認，不能只將共用服務的 today 改成過去就強制執行。未來完整歷史補跑另行設計。
- 只能使用原接續時點已付款且符合條件的票券，不能把補跑時才購買／付款的票券回填為過去的資格。
- 課程耗盡的 `ended_at` 仍記課程結束時間；票券效期按台灣日期，付款、耗盡及實際處理等事件保留精確時間。
- 本輪只確認 B 與接續的職責拆分，不修改共用服務既有啟用日期公式、續約可購買期限、取消重訂期限或原本方案資格。
- 保留既有非單堂票優先與單堂票讓位規則，整合共用生命週期服務，不複製另一套進場／背景工作專用排序。

### 4.1 第一版接續拆分及已接受代價（2026-10-23）

- B 不呼叫下一張票啟用，不設獨立接續排程／重跑工作，也不單為拆分新增資料表；既有核銷防重欄位等必要調整仍另行提出，不等於承諾完全零 schema 變更。
- B 完成後，下一張票不保證立即 Active，可能維持排隊直到下次進場／下一堂 A；一直留館者仍由下一堂 A 呼叫共用服務，不會因沒有新進場事件而漏掉接續機會。
- 接續與後續資格檢查屬後續呼叫端的交易；失敗只影響該學生後續進場／出席處理，保留原因，不能回滾或重扣已完成的上一堂 B，也不能假裝下一張票已啟用。
- 接續前先檢查該學生必要的前置結算已完成，不能先整理票券再用前置未完成理由掩蓋已寫入的接續。此順序待程式對齊及驗證，不表示目前所有入口已符合。
- 正常啟用沿用共用服務的付款、生效日期、非單堂票優先及單堂票讓位規則；本次拆分不新增另一套起日計算，也不以「跨日未完成工作轉人工」阻擋無前置異常的正常新進場。
- 接受的代價為啟用延後與錯誤較晚暴露；跨日未完成的 A／B 即使有固定資料也需人工處理。學生詳細頁的處理入口仍是上線前必要待辦。

### 5. 異常保存與人工入口

- 本階段須保存處理狀態、失敗原因、預定／實際執行時間及重試紀錄，供追溯與後續人工查閱。
- 暫時性錯誤採可恢復重試；資料／資格衝突轉人工確認，不因按下重試就強制扣堂；已完成項目不可再次扣堂。
- 2026-10-16 已確認：第一版人工查閱／更正／重新處理入口放學生詳細頁，Admin 查看原因與預計影響後確認，由後端重驗；Schedule 保持排課、不加結算操作。先前課程場次詳細資訊提案不採作第一版入口，獨立 Classes 總覽頁列後續擴充。
- 上一堂修復成功，系統才依原順序恢復該學生後續暫停的未完成工作；截止已過仍依原歷史，不用現在館內狀態或事後買票補資格，衝突未消除就保留待確認，不跳過、不重扣。
- 館內狀態更正只當下生效；歷史出席／扣堂另建案件，Admin 自行確認、整筆 Reverse、不任意調額度。已影響後續票券或反覆撤銷後補認先待確認，不一鍵再次扣退；詳見 [階段 06](../06-人工操作與異常處理/impelment_rule.md)。
- 台灣午夜換日後，昨日殘留不能成今日出席；昨日未完成 A／B 轉人工並保留原場次、歷史、出席／占用，不自動補扣。日切不依賴午夜工作一定成功，已完成項目不得重扣。

## 驗收案例

- 20:00 下課，20:10:00 不執行 B，超過該整點且同日才可開始；回場截止不因背景 tick 競態提前縮短。
- 人工與 B 並行結算同一 attendance_sn：先取得鎖者完成，後取得鎖者核對既有 Consume 不重扣；不依賴新扣堂唯一約束。
- 暫時性錯誤最多嘗試 3 次、間隔至少 15 秒；資料衝突／不明核銷立即人工，跨日停止重試。
- 收到 B 處理中回覆：無開門指令，停止轉圈、清空電話、顯示重新輸入提示；不輪詢、不自動重送，重按須重新輸入電話及重驗。
- B 已完成而沒有任何畫面查詢：後端進度仍保存；一直留館者不需重輸電話即可由下一堂 A 觸發後續資格檢查。
- B 重跑、服務重啟及交易失敗重試，都不重複扣堂。
- A、B 都晚跑：名單依歷史截止時間，先 A 後 B。
- 上一堂 B 與下一堂 A 同時到期，只剩一堂時不重複使用額度。
- 同堂中途離場仍扣；月票零扣堂。
- 半批學生已結算後失敗，恢復只處理未完成者。
- 耗盡後生命周期及快照一致，且保存可追溯的業務時間。
- 十人中一人異常：其餘九人完成；該人保留原因並暫停下一堂資格確認，不誤標 Ineligible，不阻擋其他學生。
- 固定票券被取消／堂數被人工調整造成衝突：停止該筆，轉人工，不換票、不扣負數、不標完成。
- A 歷史不足：不以現在名單補出席，不扣堂，保留待確認；其他具完整依據者正常結算。
- 來源 10/15 20:00 耗盡，已有符合條件且付款完成的續約票：允許 10/15 當天接續參加後續場次；日期到期來源則仍依到期隔天／付款日期規則。
- 10/15 的 A 或 B 到 10/16 仍未完成：轉 NeedsReview，不自動補扣或重算接續效期；保存原始資料交人工確認，不得使用 10/16 才購買／付款的票回填 10/15。
- 區分原本 Ineligible 與原本 Eligible 的結算故障；後者不能被「不補結算」規則直接消除。
- 重試保留原因及紀錄；資料衝突不以盲目重試強制扣堂。學生詳細頁由 Admin 確認並重新處理，後端重驗；上一堂成功才依序恢復該人未完成工作，其他人不受阻擋。
- 今日午夜服務未啟動：今日不能使用昨日殘留認出席；昨日未完成 A／B 留待人工確認，不自動扣堂。館內當下更正不能自動回溯改扣堂。
- 已影響後續票券或反覆更正案件，重試不得一鍵再次扣退或恢復舊票 Active；以上均尚未執行驗收。
